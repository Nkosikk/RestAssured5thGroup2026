# Rest Assured API Test Framework

[![Java CI with Maven](https://github.com/Nkosikk/RestAssured5thGroup2026/actions/workflows/maven.yml/badge.svg)](https://github.com/Nkosikk/RestAssured5thGroup2026/actions/workflows/maven.yml)

An automated API testing project for the [Ndosi Automation API](https://ndosiautomation.co.za/APIDEV). The framework uses Java, REST Assured, TestNG, and Maven to exercise user registration, administrator authentication, user approval, and registration validation.

## Features

- Fluent HTTP request and response validation with REST Assured
- Test orchestration and dependencies with TestNG
- Positive and negative registration scenarios
- Dynamic user data generated by JavaFaker
- Reusable request and JSON payload builders
- Authentication token and user ID extraction for dependent requests
- Test severity and descriptions for Allure reporting
- Automated Maven test execution through GitHub Actions

## Test coverage

The suite in `NdosiAutomationAPITests` currently covers:

| Scenario | Endpoint | Expected status | Severity |
| --- | --- | --- | --- |
| Register a new user | `POST /register` | `201 Created` | Blocker |
| Log in as an administrator | `POST /login` | `200 OK` | Blocker |
| Approve the registered user | `PUT /admin/users/{userId}/approve` | `200 OK` | Blocker |
| Register with mismatched passwords | `POST /register` | `400 Bad Request` | Blocker |
| Register with an existing email address | `POST /register` | `400 Bad Request` | Critical |
| Register with an incorrect group ID | `POST /register` | `400 Bad Request` | Normal |

The registration, administrator login, and approval tests form an end-to-end flow. TestNG method dependencies ensure the user is created before login and approval are attempted.

## Prerequisites

Install the following before running the project:

- [JDK 21](https://adoptium.net/temurin/releases/?version=21)
- [Apache Maven 3.9+](https://maven.apache.org/download.cgi)
- Git
- Internet access to Maven Central and `https://ndosiautomation.co.za`

Confirm the installations:

```bash
java -version
mvn -version
git --version
```

`mvn -version` should report Java 21.

## Getting started

1. Clone the repository:

   ```bash
   git clone https://github.com/Nkosikk/RestAssured5thGroup2026.git
   cd RestAssured5thGroup2026
   ```

2. Review the environment-specific values in:

   - `src/test/java/Common/BasePaths.java`
   - `src/test/java/Common/CommonTestData.java`

3. Download the dependencies and compile the project:

   ```bash
   mvn clean test-compile
   ```

The test suite calls a shared remote API and creates user records. Use an approved test environment and valid test credentials.

## Running the tests

Run the complete suite:

```bash
mvn clean test
```

Run only the main test class:

```bash
mvn -Dtest=Tests.NdosiAutomationAPITests test
```

Run one independent test method:

```bash
mvn -Dtest=Tests.NdosiAutomationAPITests#registerUserWithDifferentPasswordTests test
```

Some methods depend on earlier methods. When targeting an individual dependent method, also run its prerequisites or execute the complete class.

REST Assured request and response logging is enabled in `RequestBuilder`, so request details and API responses are displayed in the console during execution.

## Test reports

### Maven Surefire and TestNG

After `mvn test`, standard reports are generated under:

```text
target/surefire-reports/
```

Open `target/surefire-reports/index.html` in a browser for the TestNG report.

### Allure

Allure result files are generated in:

```text
allure-results/
```

To view them, install the [Allure command-line tool](https://allurereport.org/docs/install/) and run:

```bash
allure serve allure-results
```

To create a static report:

```bash
allure generate allure-results --clean -o allure-report
allure open allure-report
```

## Framework design

### Request flow

```text
Test method
    |
    v
RequestBuilder
    |
    +--> PayloadBuilder --> Gson JSON body
    |
    v
Ndosi Automation API
    |
    v
REST Assured response assertion
```

### Shared state

`RequestBuilder` extracts two values used by the end-to-end flow:

- `userId` from the registration response at `data.id`
- `token` from the login response at `data.token`

The approval request sends the token as a Bearer token and includes the registered user's ID in the endpoint path.

### Dynamic data

`GenerateTestData` creates a random first name, last name, email address, and password when the class is loaded. This reduces email collisions during successful registration tests. The existing-email test intentionally reuses the generated email after the successful registration test.

## Configuration and test data

The current project keeps its API URL and shared test values in Java classes:

| Setting | Location |
| --- | --- |
| API base URL | `Common/BasePaths.java` |
| Administrator credentials | `Common/CommonTestData.java` |
| Group ID | `Common/CommonTestData.java` |
| Expected HTTP status codes | `Common/CommonTestData.java` |
| Request content type | `Common/ContentType.java` |

`src/test/resources/property.properties` is available for future externalized configuration but is currently empty.

> **Security:** The current test configuration includes credentials in source code. Do not add production credentials or other secrets to the repository. Prefer environment variables or encrypted CI secrets when extending the framework.

## Continuous integration

The workflow in `.github/workflows/maven.yml` runs on every push and pull request targeting `main`. It:

1. Checks out the repository.
2. Installs Temurin JDK 21.
3. Enables Maven dependency caching.
4. Runs `mvn clean test` on Ubuntu.

Workflow runs are available on the repository's **Actions** tab.

## Adding tests

1. Add or reuse a JSON builder in `payloadBuilder/PayloadBuilder.java`.
2. Add a reusable API operation in `requestBuilder/RequestBuilder.java`.
3. Add expected status codes or shared test data under `Common`.
4. Add a TestNG method to `Tests/NdosiAutomationAPITests.java`.
5. Annotate the test with `@Description` and an appropriate Allure `@Severity`.
6. Assert the response status and any required body or header values.
7. Run `mvn clean test`.

Example assertion pattern:

```java
createUserResponse(firstName, lastName, email, password, confirmPassword, groupId)
        .then()
        .assertThat()
        .statusCode(Creation_Success);
```

Use `dependsOnMethods` only when a scenario requires state produced by another test. Keep independent validation tests independent so they can run in isolation.

## Troubleshooting

### Tests cannot reach the API

Confirm that `https://ndosiautomation.co.za/APIDEV` is reachable and that a firewall, VPN, or proxy is not blocking the request.

### Authentication or approval fails

Check the administrator credentials and group ID in `CommonTestData.java`. These values must be valid for the configured API environment.

### A dependent test is skipped

TestNG skips a dependent method when its prerequisite fails. Review the first failed method in the registration-login-approval chain.

### Generated email already exists

Run the suite again to generate a different email address. If collisions continue, review the email generation logic in `GenerateTestData.java`.

### No Allure report opens

Verify that the Allure CLI is installed and available on `PATH`, then run `allure serve allure-results` after the tests have produced result files.
